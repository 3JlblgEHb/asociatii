# Property domain baseline

Реализовано 28 августа 2026 года миграциями `00004–00006`.

## Модель

```text
organizations (APC)
└── condominiums
    └── buildings
        └── property_units
            ├── property_ownerships → persons
            ├── property_occupancies → persons
            └── property_mandates → persons
```

`organization_members` отвечает только за доступ и роль в APC. Владение недвижимостью больше не хранится в membership.

## Инварианты

- кондоминиум принадлежит одной APC;
- здание может ссылаться только на кондоминиум той же APC;
- кадастровый объект может ссылаться только на здание и кондоминиум той же APC;
- person существует в контексте APC и может быть связан с учётной записью либо существовать без регистрации;
- объект поддерживает нескольких совладельцев;
- права собственности имеют период действия и не удаляются при смене собственника;
- сумма активных долей одного объекта не может превышать 100%; конкурентные изменения сериализуются блокировкой объекта;
- жительство/аренда отделены от права собственности;
- представитель и доверитель являются отдельными persons, mandate имеет scope и срок;
- RLS и составные foreign keys одновременно защищают tenant boundary.

## Перенос старой модели

- `apartments` преобразована в `property_units` с сохранением UUID;
- квартира стала типом `apartment`, дополнительно поддержаны commercial, parking, storage и other;
- для каждой существующей APC создан исходный condominium;
- здания привязаны к condominium;
- зарегистрированные собственники перенесены в `persons` и `property_ownerships`;
- `organization_members.apartment_id` и `property_units.owner_id` удалены;
- обращения и простые MVP-голоса ссылаются на `property_unit_id`;
- старый маршрут `/apartments` и старый React-компонент удалены, используется `/properties`.

## Атомарные workflows

- `create_organization` создаёт APC, администратора, person, исходный condominium и audit event;
- `accept_organization_invitation` создаёт/обновляет membership и person одной транзакцией;
- `create_property_unit` проверяет tenant/condominium/building, создаёт объект, начальное ownership и audit event одной транзакцией.

## Временное ограничение MVP-голосования

Текущий модуль `votes` остаётся простым опросом: для пользователя выбирается первый активный объект с правом голоса. Это не юридический модуль общего собрания. Перед реальными собраниями он будет заменён snapshot-моделью реестра, долей, доверенностей, кворума и правил конкретного решения.
